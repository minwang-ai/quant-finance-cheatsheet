    Command Purpose Parameters / Options Example
    ls Lists files and directories in the current directory or a specified path. -path (optional): directory to list ls
    ls /home/user
    cp Copies a file or directory to another location. -source: file/directory to copy
    - destination: target path
    - -r: copy directories recursively    		 cp notes.txt backup.txt
    cp -r folder1 folder2

    - destination: target path or new name    		 mv old.txt new.txt
    mv file.txt docs/
    rm Removes files or directories. file: file to remove
    -r: remove directories recursively
    -f: force removal    		 rm temp.txt
    rm -r old_folder
    mkdir Make a new directory (folder). - directory_name: name of the new directory
    - -p: create parent directories as needed    		 mkdir projects
    mkdir -p week1/src
    cd Changes the current working directory. - directory (optional): target directory,
    , e.g.,.. means parent directory
    and ~ means home directory    		 cd documents
    cd ..
    cd ~
    rmdir Removes a directory. directory_name: empty directory to remove rmdir empty_folder
    clear Clears the terminal screen. None clear

    Core Programming Concepts¶

    Concept Description Notes
    Bugs Natural normal mistakes or problems in code to be solved. Error messages can often inform you of your mistakes and provide clues on how to fix them. However, there will be many times when the interpreter is not this helpful.
    Avoid using global variables.
    Variables Containers for storing values within your program in the computer memory. Avoid hard coding! Use variables to store the values to use them later
    Assignment = Assign (copy) the value on the right to the variable on the left.
    Comments Developer notes are used to track intentions for a block of code and write todo list (pseudo code) to break a bigger program down into small tasks and structure your code - single line: # or
    - multiple lines: Three Double quotes """ comments """
    Readability and simplicity prioritize readability over brevity. use comments to clarify logic. Do not nest too much with multiple parentheses ((()))
    Consistency use a consistent coding style We can use either double quotes " " or single quotes ' ' as long as it is consistent. Sometimes though it is necessary to alterante, if we are already using double quotes for outer layer, to avoid confusion and syntax errors, use single quotes for inner layer.
    naming snake_case (words are separated by underscores _, with all letters in lowercase. )

    Function Terminology¶

    Term Definition Notes
    Function verbs or actions that let we do something that the computer or computer language already know how to perform Functions takes intput (arguments/ parameters) as input and produce output (return value).
    Arguments The actual input values passed to a function to influence its behavior. Parameters and arguments are the same thing, but using different terms in different places.
    Parameters (input) Placeholders in the function definition determining what it can take. - Positional parameters: passing with orders
    - Named parameters: optional, e.g., sep, end.
    Return Value (output) A value "passed back" from a function when function ends - we can use it directly or store it in a variable to use it later in the program.
    - If we use break to break out of a loop and then immediately return a value, we can use return directly to combine these two operation - break then return.
    Nesting functions Running functions inside of other functions. The inner one executes first, so the return value of the inner function becomes the argument of outer function. e.g. x = int(input("What's x? "))
    Chain methods Combine methods for readability and simplicity e.g., name.strip().title()
    Scope A variable only exists within the context (block) where it is defined. we can only use the variables there

    Style - PEP 8¶

    PEP 8 is the official Python Enhancement Proposal that codifies standards for how Python code should look.

    Core Principles¶

    Principle Description
    Readability The overarching premise of PEP 8: "Readability counts".
    Consistency Consistency is vital within a project, and most important within a single module or function.

    PEP 8 Formatting Standards¶

    Feature Rule / Guideline
    Indentation Use four spaces per indentation level.
    Tabs vs. Spaces Use spaces instead of tabs (VS Code can be configured to convert tabs to spaces).
    Line Length Avoid long lines that require horizontal scrolling; keep code within the reasonable maximum length.
    Blank Lines Use blank lines between blocks of code and comments to avoid a "wall of text".
    Imports Place import and from statements at the top of the file following specific prescribed patterns.
    Whitespace Use general whitespace to make logical blocks easier to understand.

    Automated Style Tools¶

    Programs that analyze or reformat your code are called linters or formatters.

    Tool Type Purpose How to use
    pylint Linter Statically analyzes code to find mistakes or style inconsistencies; can be "noisy" and overwhelming for beginners.
    pycodestyle Formatter automatically reformats code to match style guidelines.
    black (recommended) Formatter A highly opinionated formatter that makes stylistic decisions for us so we can focus on solving problems. black file.py
